# 参考文章风格分析

## 原则

目标是学习“为什么读起来顺”，而不是复制“原文怎么说”。优先分析 3–8 篇同一作者或同一站点的代表文章；只有一篇时，将结论标记为低置信度，避免把主题偶然性误判为稳定文风。

若参考对象是具体作者，尤其是仍在创作的作者，只总结高层特征并形成新的混合表达，不宣称精确复刻其个人声音。

## 分析步骤

### 1. 分离三类信息

- **稳定结构**：多篇都出现的开头、推进、示例、转折和收束方式。
- **主题特征**：仅由当前技术主题决定的术语、代码和案例。
- **不可复用表达**：独特比喻、故事、句式、口头禅、标题和示例。

只把第一类写入风格契约。第二类重新研究，第三类禁止复用。

### 2. 建立风格指纹

按 1–5 级记录倾向，不追求伪精确统计：

| 维度 | 观察问题 |
|---|---|
| 开场方式 | 结论先行、问题场景、故事、反常识还是定义？ |
| 信息顺序 | 直觉→定义、问题→方案、代码→原理还是历史→现状？ |
| 章节节奏 | 每节长度是否接近？是否固定以例子或小结结束？ |
| 难度曲线 | 概念是缓慢增加还是快速进入内部机制？ |
| 认知预算 | 每节引入多少核心术语，数学/代码深度如何变化，是否有快速路线？ |
| 解释层次 | 是否同时提供直觉、精确定义、实现和边界？ |
| 例子密度 | 每个概念是否都有例子、反例或可运行代码？ |
| 证据方式 | 文档、论文、源码、实验、图表或经验复盘？ |
| 语言语气 | 正式/对话、肯定/审慎、第一/第二/第三人称？ |
| 句段节奏 | 短句、短段、列表、问句和过渡句的使用方式？ |
| 术语策略 | 首次定义、括号解释、术语表还是默认读者已知？ |
| 视觉结构 | 图、表、代码、引用框、提示框的角色？ |
| 结尾方式 | 摘要、决策表、练习、下一步还是开放问题？ |
| 理解验证 | 是否有检查点、迁移问题、真实读者测试或明确的未验证披露？ |

### 3. 提炼风格契约

输出三部分：

```text
保留：
- 例如：每个复杂概念先给直觉图景，再给精确定义。
- 例如：每个实现步骤都展示预期输出与失败信号。

避免：
- 例如：长篇背景后才回答读者问题。
- 例如：连续引入多个缩写而不解释。

原创替代：
- 使用新的贯穿案例、图示、数据和比喻。
- 调整章节颗粒度，使其匹配本次读者，而非参考文章读者。
```

### 4. 脱离原文重构

风格画像完成后，不再沿着参考文章逐段改写。先基于读者目标建立知识依赖，再生成全新大纲。事实与观点回到原始证据，而不是把参考文章当作事实来源。

### 5. 相似性自检

逐项确认：

- 是否复用了非通用的标题或小标题？
- 是否复用了同一个故事、类比、反例或代码组织？
- 是否保留了参考文章特有的句子节奏和口头禅组合？
- 是否只是替换同义词而保持原段落逻辑？
- 离开参考文章后，本文是否仍能从读者目标独立推导出来？

任一项为“是”，重写对应部分。
