# 技术内容结构模式

先选一个主模式。其他模式可作为局部组件，但不要让读者在“跟着做”和“理解为什么”之间频繁切换。

## 教程 Tutorial

**目标**：带领学习者第一次完成一个有意义的结果。

结构：

1. 最终成果预览。
2. 前置条件与环境。
3. 小步执行，每步都有验证。
4. 完整结果与回顾。
5. 清理、扩展和下一篇。

写作重点：保证成功路径；解释够用即可，深层原理链接到解释文章。

## 操作指南 How-to

**目标**：帮助已有基础的读者完成一个具体任务。

结构：

1. 适用场景与直接答案。
2. 输入、限制和风险。
3. 按任务顺序给步骤。
4. 选项、验证、回滚和排障。
5. 相关任务链接。

写作重点：少背景、强可执行性；不要把它写成入门课程。

## 原理解释 Explanation

**目标**：建立心理模型，回答为什么和如何运作。

结构：

1. 核心问题与一句话答案。
2. 直觉模型。
3. 关键组成与机制。
4. 一个贯穿例子。
5. 反例、边界与权衡。
6. 与相邻概念比较。
7. 决策总结与深入阅读。

写作重点：因果关系、边界与多层解释；避免只罗列定义。面向 `absolute_beginner` 且预计超过 10 分钟时，增加同页快速路线，把公式、源码和性能细节放到可选进阶层。

## 参考 Reference

**目标**：让读者准确查询事实，而非顺序学习。

结构：

1. 范围、版本与稳定性说明。
2. 术语、接口、参数或配置项。
3. 返回值、错误、默认行为和兼容性。
4. 最小示例。
5. 相关项交叉链接。

写作重点：一致、完整、可扫描；不要用长故事隐藏事实。

## 排障 Troubleshooting

**目标**：从症状快速定位原因并恢复。

结构：

1. 症状与影响范围。
2. 快速安全检查。
3. 决策树：信号 → 可能原因 → 验证。
4. 修复与回滚。
5. 根因解释与预防。

写作重点：按观察信号排序，不按作者脑中的组件排序；高风险操作必须先备份或提供回滚。

## 比较与选型 Comparison

**目标**：帮助读者做出有条件的选择。

结构：

1. 决策场景和候选范围。
2. 明确评价维度与权重来源。
3. 同一环境下的对比证据。
4. 按维度解释权衡。
5. 按场景给建议，而非宣布唯一赢家。
6. 未知项、成本和迁移风险。

写作重点：基准环境透明；区分事实数据与主观权重。

## 案例研究 Case study

**目标**：展示真实约束下的决策和结果。

结构：

1. 背景、约束与初始状态。
2. 可选方案与选择理由。
3. 实施过程和关键转折。
4. 测量方法与结果。
5. 失败、意外和适用边界。
6. 可迁移经验与不可迁移部分。

写作重点：展示方法和证据，不把相关性写成因果性，不伪造“真实项目经验”。

## 观点/深度分析

**目标**：提出并论证一个可检验的技术判断。

结构：

1. 论点与适用范围。
2. 最强支持证据。
3. 最强反方观点。
4. 逐项回应和不确定性。
5. 对工程决策的含义。
6. 未来验证条件。

写作重点：公平呈现反方；把预测、推断和事实分开。
