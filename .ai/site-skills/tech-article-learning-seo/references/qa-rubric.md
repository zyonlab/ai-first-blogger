# 质量评分、验证范围与返工门禁

## 先声明验证范围

评分之前必须先报告“实际检查了什么”。自动工具的通过不得写成全文质量通过。

```yaml
validation_scope:
  automated_structure: "not_run | passed | issues_found"
  cognitive_budget: "not_run | checked | exceeded_with_reason | issues_found"
  source_traceability: "not_run | passed | issues_found"
  source_semantics: "not_run | source_checked | peer_reviewed | issues_found"
  code_or_experiment: "not_applicable | not_run | verified | partially_verified | failed"
  target_reader_test: "not_run | self_check_only | pilot_run | target_reader_passed | needs_revision"
  similarity_review: "not_run | checked | issues_found"
```

建议同时给发布置信度：

- `draft`：只完成初稿；
- `structure_checked`：通过自动结构与预算检查；
- `source_verified`：核心主张完成语义核验；
- `reader_pilot`：完成小规模目标读者试读；
- `reader_validated`：按预设标准通过目标读者测试；
- `publish_ready`：所有任务所需门禁均完成，且未核验项已披露。

“structure_checked”不等于“publish_ready”。

## 评分

总分 100。建议发布线为 85；任何硬门禁失败时，即使总分高也不得直接发布。

| 维度 | 分值 | 核心问题 |
|---|---:|---|
| 技术正确性 | 20 | 主张、代码、版本、数据和边界是否准确可验证？ |
| 学习设计 | 20 | 是否匹配读者、遵守认知预算、依赖清楚，并能完成目标？ |
| 结构与可读性 | 15 | 标题能否讲清路径，句段、图、代码是否降低负担？ |
| 证据与信任 | 15 | 引用是否语义支持主张，范围和强度是否一致，方法是否透明？ |
| 搜索意图与发布 SEO | 15 | 是否准确满足单一主意图，标题摘要内链是否诚实清楚？ |
| 原创与非同质化价值 | 10 | 是否有独特分析、实验、图、案例方法或综合判断？ |
| 系列一致性 | 5 | 单篇可记满；系列看依赖、术语、内链与内容边界。 |

## 评分锚点

### 技术正确性 0–20

- 18–20：关键主张均有合适证据；代码/命令已验证；版本、假设和例外清楚。
- 13–17：整体正确，有少量非关键未验证项并明确标注。
- 7–12：存在重要缺口、模糊边界或环境不可复现。
- 0–6：核心结论、代码或数据不可靠。

### 学习设计 0–20

建议按四项各 5 分：

1. **读者匹配与预算**：读者等级、阅读时长、术语、数学和代码预算一致。
2. **依赖与递进**：概念按依赖推进，没有多维度突然跳跃。
3. **理解闭环**：有直觉、定义、例子、边界、检查点和迁移问题。
4. **验证诚实性**：清楚区分作者自检、自动检查和真实目标读者测试。

- 18–20：四项完整；超出预算有明确理由；读者能沿主路径完成目标。
- 13–17：主路径清楚，但个别概念跳跃、预算失衡或检查点不足。
- 7–12：更像知识堆叠，读者难以形成完整模型。
- 0–6：目标不清，前置缺失，无法完成承诺。

没有真实读者测试不自动扣为不及格，但不得声称“已验证好懂”；应在 `validation_scope` 中写明。

### 结构与可读性 0–15

- 13–15：扫读标题即可理解逻辑；段落职责单一；视觉材料紧贴概念；长文有快速路线。
- 9–12：可读但有冗长、重复、顶层章节过多或局部层级问题。
- 5–8：大段文字、标题空泛、术语密集或主路径被进阶细节打断。
- 0–4：结构阻碍理解。

### 证据与信任 0–15

建议按五项各 3 分：

1. 来源层级适合主张；
2. 来源实际支持相邻主张；
3. 版本、范围和适用条件一致；
4. 正文措辞没有超过证据强度；
5. 方法、限制、冲突证据和未核验项透明。

- 13–15：核心主张完成语义核验，来源一手，证据链和限制透明。
- 9–12：来源可靠，但部分主张只完成链接完整性或范围披露不完整。
- 5–8：大量二手总结、引用错位，或经验被写成普遍事实。
- 0–4：引用虚构、错配、不可追溯，或证据明确反驳正文。

仅运行 `article_lint.py` 不能获得“引用语义已核验”的分数。使用 [evidence-validation.md](evidence-validation.md) 和 evidence ledger。

### 搜索意图与 SEO 0–15

- 13–15：一页一意图；标题、H1、摘要、正文一致；链接和元数据清楚独特；理解难度承诺可兑现。
- 9–12：基本匹配，存在轻微重复、遗漏或标题措辞偏强。
- 5–8：关键词驱动、承诺模糊、覆盖分散或用“小白必懂”等词替代学习设计。
- 0–4：点击诱导、堆砌、重复页或搜索优先于读者。

### 原创价值 0–10

- 9–10：提供难以复制的实验、源码分析、数据、原创图、方法或综合洞见。
- 6–8：至少有一个明确的原创价值锚点，例如贯穿案例、决策框架或多来源冲突综合。
- 3–5：主要是已有资料重组，缺少新验证或独特解释。
- 0–2：近似复制、同义改写或批量模板内容。

长篇技术文建议至少选择一个主要原创锚点：可复现实验、源码追踪、原创图、决策框架、完整 worked example 或跨一手来源综合。

## 硬门禁

出现以下任一项，状态为 `BLOCKED`：

- 核心事实、引用、数据、案例、读者反馈或实验结果为编造。
- 标题承诺与正文实际交付不一致。
- 高风险命令无警告、备份、验证或回滚。
- 代码声称可运行但未验证，且未披露。
- 关键前置概念缺失导致主路径无法完成。
- 核心引用不能支持相邻主张，或来源与正文结论相反。
- 将 `partial` 证据写成无条件结论，且未加入限定。
- 标记为 `peer_reviewed` 或 `target_reader_passed`，却没有真实记录或审阅者。
- 复用参考文章的独特表达、案例、代码或叙事骨架。
- 关键词堆砌、批量近似页面、伪造更新时间或其他搜索操纵行为。

## 必须返工但不一定阻止发布的情况

状态至少为 `REVISE`：

- `absolute_beginner` 长文没有快速阅读路线，且顶层学习步骤过多。
- 全文新术语或单节概念密度明显超过 brief 预算，未说明原因。
- 数学或代码深度超过目标读者预算。
- 只有定义，没有例子、边界、检查点或迁移问题。
- 核心主张只有二手来源，且能合理找到一手来源。
- 自动检查被描述为“技术正确”或“读者已理解”。
- 标题含“保证看懂、人人都懂、彻底掌握”等未经验证的理解承诺。

## 最终审计输出

```yaml
status: PASS | REVISE | BLOCKED
score: 0
release_confidence: draft | structure_checked | source_verified | reader_pilot | reader_validated | publish_ready
validation_scope:
  automated_structure: not_run
  cognitive_budget: not_run
  source_traceability: not_run
  source_semantics: not_run
  code_or_experiment: not_applicable
  target_reader_test: not_run
  similarity_review: not_run
scores:
  technical_accuracy: 0
  learning_design: 0
  structure_readability: 0
  evidence_trust: 0
  search_intent_seo: 0
  originality: 0
  series_coherence: 0
blocking_issues: []
high_priority_revisions: []
optional_improvements: []
unverified_items: []
```

高优先级修改按“会导致错误决策 → 无法完成任务 → 核心误解 → 认知负担 → SEO 发布细节”的顺序排列。

## 自动工具的正确表述

- `article_lint.py`：检查 Markdown 结构、认知预算元数据、粗略阅读负担和引用编号完整性。
- `evidence_lint.py`：检查主张台账完整性、正文标记和引用可追踪性。
- `series_lint.py`：检查系列元数据、依赖、导航、意图重叠和部分连续性风险。

通过时写“未发现可自动识别的问题”，不要写“文章质量已验证”。

## 系列写作专项审计

系列不能只看单篇平均分，还要检查端到端学习路径：

| 检查项 | 通过条件 |
|---|---|
| 单篇完整性 | 任意子文章都能独立兑现标题承诺，不靠下一篇补齐关键答案。 |
| 累积增量 | 每篇明确继承状态并增加一个新能力，不是重复介绍同一主题。 |
| 认知连续性 | 相邻篇的读者等级、数学和实现复杂度只合理提升，跳跃有桥接。 |
| 依赖有效性 | 前置存在、无循环、无未来知识偷跑，相邻难度跳跃可解释。 |
| 贯穿案例连续性 | 环境、代码、数据和命名的变化都有记录、快照和验证。 |
| 证据连续性 | 核心主张、来源版本和冲突结论在全系列台账中可追踪。 |
| 搜索边界 | 每页主要意图与独特交付可区分，没有批量近似页面。 |
| 终点闭环 | 终章或综合任务能够验证系列声明的最终能力。 |
| 导航准确性 | 总览、上一篇、下一篇、前置和完成状态与实际文件一致。 |

若任一核心检查项失败，`series_coherence` 不得高于 2/5；若出现依赖循环、正文缺失却标记完成、虚构读者测试或多篇近似复制，则状态为 `BLOCKED`。
