# Recipe: add a content type

Adding "Tutorials" alongside posts, videos, projects and case studies.

**Cost**: 1 yaml block, 1 engine file, 2 lines in the registry, 1 content directory.
No pages, no routes, no navigation edit, no `llms.txt` edit, no home page edit.

A content type has two halves, split by who owns the decision — what it is called
and where it appears is yours; how it validates and renders is the engine's.

The engine's types are a **menu**: it ships four, and `site/content-types.yaml`
decides which ones this site publishes. Deleting a key removes the type entirely
— routes, nav entry, `llms.txt` section — which is how a site that does not make
videos gets rid of `/videos/`. Declaring a key the engine has no module for is
still an error.

This recipe adds a type to the engine, so it applies when you own the engine
(this repository). A site that installs `aifb-engine` as a dependency can
choose from the menu but cannot yet extend it.

This walkthrough was executed against the repository; the verification numbers at the
bottom are measured, not estimated.

## 1. Declare the half you own

`site/content-types.yaml` — what it is called, its URL, and where it shows up:

```yaml
tutorials:
  route: tutorials              # /tutorials/ and /tutorials/<slug>/
  label: Tutorial               # singular, used in breadcrumbs and eyebrows
  listTitle: Tutorials
  listDescription: 分步骤的实操教程，每篇给出目标、前置条件、步骤和验收标准。
  surfaces:                     # omitting a surface means "not there"
    nav: 15                     # sort weight; omit to stay out of the nav
    home: { limit: 2, order: 25 }
    rss: true
    llms: { limit: 6 }
    sitemap: true
```

### `routeAtRoot`, for a site with exactly one type

A site that publishes only articles still pays for the segment:

```
/writing/apps-ignore-system-proxy/
 ^^^^^^^ carries no information — there is nothing else an entry could be
```

```yaml
posts:
  route: writing
  routeAtRoot: true     # entries at /apps-ignore-system-proxy/
```

`route` is still required and still serves the **list** page: `/writing/`
keeps the archive, its `ItemList` and its nav entry, and `/` stays the landing
page. Only the entry URLs move.

Refused at build time if a second type is published — the segment is what tells
their entries apart — and refused if an entry slug collides with an archive, a
fixed page or a locale prefix, since every slug is now a top-level URL segment.

## 2. Declare the half the engine owns

`packages/engine/content-types/tutorials.ts`:

```ts
import { z } from 'astro:content';
import { absoluteUrl } from '../lib/seo';
import { defineContentType } from './types';

export default defineContentType({
  name: 'tutorials',        // must equal the directory under content/

  card: 'ArticleCard',      // reuse an existing card…
  detail: 'PostDetail',     // …and an existing detail component
  listLayout: 'grid two',
  sortBy: 'pubDate',

  schema: z.object({
    title: z.string(),
    description: z.string(),
    slug: z.string(),
    pubDate: z.coerce.date(),
    draft: z.boolean().default(false),
    category: z.string(),
    tags: z.array(z.string()).default([]),
    level: z.enum(['beginner', 'intermediate', 'advanced']).default('beginner'),
  }),

  jsonLd: (entry, { canonical }) => [{
    '@context': 'https://schema.org',
    '@type': 'HowTo',
    name: entry.data.title,
    description: entry.data.description,
    url: absoluteUrl(canonical),
  }],

});
```

### Reusing components vs. writing new ones

`card` and `detail` name files under `packages/engine/components/cards/` and
`packages/engine/components/details/`. Reuse an existing pair when the shape fits — above,
tutorials render exactly like posts. Write a new one only when the type genuinely
needs a different treatment; that is real design work, not boilerplate.

A missing component throws at build time with the available names listed.

## 3. Register it

`packages/engine/content-types/index.ts` — two lines:

```diff
 import projects from './projects';
+import tutorials from './tutorials';
 import videos from './videos';

-export const registry: ContentTypeDef[] = [posts, videos, projects, caseStudies];
+export const registry: ContentTypeDef[] = [posts, videos, projects, caseStudies, tutorials];
```

## 4. Add content

`content/tutorials/deploy-to-cloudflare.mdx` — filename must equal `slug` (C-08),
and the body needs ≥ 2 internal links (C-02).

## 5. Verify

```bash
pnpm build && pnpm validate
```

## What you get without writing it

Measured on the real run of this recipe:

| Surface | Result |
|---|---|
| `/tutorials/` list page | generated by `packages/engine/pages/[type]/index.astro` |
| `/tutorials/<slug>/` detail page | generated by `packages/engine/pages/[type]/[slug].astro` |
| Navigation entry | `Tutorials`, positioned by `nav: 15` |
| Home section | 2 entries, positioned by `order: 25` |
| `llms.txt` | section header + entries |
| `rss.xml` | merged and re-sorted with the other feeds |
| Sitemap | included |
| Breadcrumbs (visible + `BreadcrumbList`) | on both pages |
| `HowTo` JSON-LD | from the `jsonLd` hook |
| `/topics/engineering-productivity/` | the tutorial appears — topic pages aggregate every type carrying a `category` |
| `pnpm validate` | 42 → 44 pages, still **0 errors** |

## Acceptance test

```bash
git status --porcelain
# ?? packages/engine/content-types/tutorials.ts
# ?? content/tutorials/
#  M packages/engine/content-types/index.ts
#  M site/content-types.yaml
```

Four paths. If a fifth appears — a page, a nav edit, an `llms.txt` edit — the
registry has been bypassed and the extensibility guarantee is broken. `pnpm metrics`
reports it as **T2**.

## Removing a type

Delete its block in `site/content-types.yaml`. That is enough: every surface drops it —
routes, nav entry, `llms.txt` section — and the engine half needs no change, which is
what lets a site that installed `aifb-engine` decline a type it cannot delete. If you
own the engine and want the module gone too, also delete
`packages/engine/content-types/<name>.ts`, its line in `index.ts`, and `content/<name>/`
— but never the module alone: a key in `site/content-types.yaml` with no engine module
is a build error naming it. Run `pnpm validate` afterwards — C-03 catches links to
pages that no longer exist.

## Gotchas

| | |
|---|---|
| `route` collides with a static page | Build fails naming the collision. Reserved: `topics`, `series`, `about`, `uses`, `newsletter`, `work-with-me`. |
| Type appears nowhere | `surfaces` is empty in the yaml. Omitting a surface means "not there"; C-04 flags the resulting orphans. |
| Want it invisible in the nav but crawlable | Omit `nav`, keep `sitemap` and `llms`, and link it from somewhere — otherwise C-04 fails. |
| `category` should use the site taxonomy | Import `isCategory` from `@config/taxonomy` and `.refine()` it, as `posts.ts` does. |
